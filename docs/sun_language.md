# 太阳语与摩斯电码

太阳语是《炽阳之心》唯一的「输入」谜题：玩家用点与划向太阳说话。实现分成两层，
两层都不访问全局服务，因此可以脱离场景单独测试。

## 码表（`scripts/sun/sun_language.gd`）

一个「太阳语字符」= 一个词 + 一字母摩斯码，取**行首字母**规则：
太阳=A(`.-`)、赤阳=B(`-...`)、塔=C(`-.-.`)、地球=D(`-..`)、人类=I(`..`)、
水星=M(`--`)、火星=N(`-.`)、苏醒=R(`.-.`)、模拟=S(`...`)、疑惑=U(`..-`)、
观测=W(`.--`)、回归=G(`--.`)、清除=K(`-.-`)。

这个设计保证两件事：每个码都是标准摩斯字母、**两两互不相同**（测试会验证唯一性），
因此按字间隔切分后任何一串电码都能无歧义还原。

## 词条与门控

| 词条 | 内容 | 允许场景 | 需要知识 | 语料序号 |
| --- | --- | --- | --- | --- |
| `death_clear` | 清除 | `sun_outer` | `know_death_clear` | 0（死亡时触发） |
| `awaken` | 苏醒 | `sun_outer` / `mercury_1` | `know_awaken` | 1 |
| `doubt` | 疑惑 | `sun_outer` | `know_doubt` | 2 |
| `ultimate` | 赤阳 / 塔 / 人类 / 回归 | `sun_outer` | `know_ultimate` | — |

`verify()` 的判定顺序与结果：

| 结果 | 触发条件 | 游戏内表现 |
| --- | --- | --- |
| `EMPTY` | 没有输入 | 忽略 |
| `UNKNOWN` | 电码不属于任何词条 | 太阳返回太阳语料 3「疑惑」（`response_error()`） |
| `LOCKED` | 电码正确但还没学会 | 「电码是对的，但你还读不懂它。」并给出点划提示 |
| `WRONG_CONTEXT` | 电码正确但不在允许的场景 | 「这串太阳语不属于这里。」 |
| `SUCCESS` | 知识与场景齐备 | 记录语料；集齐 0/1/2 后学会终极太阳语 |

集齐三段语料时 `_check_all_fragments()` 会写入 `know_ultimate` 并学习全部码表，
此后在太阳外层发送终极太阳语即写入 `ultimate_sent`（通往结局）。

## 输入（`scripts/sun/morse_input.gd`）

| 行为 | 结果 |
| --- | --- |
| 短按（≤ `dot_max_seconds`，默认 0.22s） | 点 |
| 长按 | 划 |
| 静默超过 `letter_gap_seconds`（0.6s） | 自动断字 |
| 等待键 | 手动断字，与静默断字产生**完全相同**的标记串 |
| 过短按压（< `repeat_guard_seconds`） | 丢弃，避免抖动误输入 |

不变量（有测试守着）：

- `effective_tokens()` 可重复调用且结果一致——UI 每帧轮询它，重复附加当前段会污染输入。
- 字间隔只在断字时写入一次；`separator()` 对空段返回 `false`，不产生重复间隔。
- 尾部字间隔只表示「这个字已结束」，比较时由 `SunLanguage.trimmed()` 去掉，因此输入中与输入完都能判定。

## 发送场景

`star_map.gd:_morse_context()` 决定当前场景：站在赤阳之塔交互范围内（或位于太阳）为 `sun_outer`，
其他行星按其当前层给出 `mercury_1` / `earth_1` 等。塔不常驻，所以最近一次发送会暂存在 `_pending_tokens`，
供「在塔附近发送」的语料定位使用。
